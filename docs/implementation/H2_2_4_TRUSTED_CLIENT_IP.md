- 사용자 영향: IP 미확인 요청이 기존의 작은 `unknown` 버킷에 묶이지 않는다. 미확인 요청도 별도 전역 한도를 받으며 무제한 허용하지 않는다.
- 남은 것 / 필요한 판정: 아래 정책과 한도 값을 검토해 달라. 승인 전 병합하지 않는다.

## 제안 정책

1. `TRUSTED_CLIENT_IP_HEADER`로 단일 신뢰 헤더를 지정한다. 배포 프록시가 클라이언트 값을 덮어쓰는 헤더여야 한다.
2. 미지정 시 `VERCEL=1`에서는 `x-real-ip`, 그 외 환경에서는 신뢰 헤더 없음이다.
3. `X-Forwarded-For`와 `Forwarded`는 명시적으로 지정해도 거부한다. 여러 값 중 첫 값을 고르지 않는다.
4. 단일 IPv4/IPv6 리터럴만 허용하고 포트·쉼표 목록·IPv6 zone 식별자는 거부한다. IPv6의 동치 표현과 IPv4-mapped IPv6는 같은 한도 키로 표준화한다.
5. IP를 모르면 시각·요청 ID·정적 경로·고정 사유만 경고 로그에 남긴다. IP/헤더 원문은 남기지 않는다.

| 작업 | 기존 개별 IP 시간당 한도 | 제안 미확인 IP 전역 시간당 한도 |
|---|---:|---:|
| 새 세션 | 12 | 1,200 |
| 공유 읽기 | 120 | 12,000 |
| 신고 | 6 | 600 |

전역 한도는 기존 한도의 100배이며 작업별 별도 policy key와 HMAC 소유자 키를 사용한다. 기존 IP별 quota row와 충돌하지 않는다. 정상 세션 쿠키 복구는 기존처럼 새 세션 한도를 소비하지 않는다. 미확인 사용자는 전역 한도를 공유하므로 운영에서 신뢰 헤더와 프록시 덮어쓰기를 검증해야 한다.

## 2026-10-10 승인 조건 반영

Orchestrator 승인에 따라 IPv6 quota owner는 /64 접두어로 묶는다. IPv4 및 IPv4-mapped IPv6는 같은 IPv4 주소 단위로 유지한다. 접두어 내부 주소 교체·인접 /64 분리·IPv4 mapped 동등성 시험을 추가했다. 기존 IPv6 주소별 window에서 접두어 window로 바뀌는 최초 시간에는 새 버킷이 시작된다. 기존 공유 데이터나 세션 형식은 바꾸지 않는다.
