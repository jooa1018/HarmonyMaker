# H2 2-2 S3 선택화와 개발용 메모리 저장소

[H2] 2-2 S3 선택화·개발 메모리 복구 — 부분(CI 후 자체 병합)

- 변경: `src/server/substrate`의 필수 S3 환경 변수와 런타임 S3 클라이언트를 제거했다. 공유 저장은 PostgreSQL을 사용한다. 명시적 `HM_DEV_MEMORY_PERSISTENCE=1` 개발 경로를 복구했다.
- 검증: 타입 검사, 구성·메모리 공유·예약 정리 집중 시험 27개, 프로덕션 빌드 통과. lint와 전체 단위 시험 1,002개(111개 파일) 통과. CI 결과는 PR에 기록한다.
- 사용자 영향: 운영 공유에 S3가 필요하지 않다. 개발에서는 DB·S3 없이 공유 기능을 시험할 수 있다. 일곱 개의 독립된 보안 키는 기존과 같이 필요하다. 브라우저 저장 형식과 실제 적용 마이그레이션은 변경하지 않는다.
- 남은 것 / 필요한 판정: B등급으로 CI 통과 후 자체 병합한다. 기존 S3 객체의 실제 삭제는 수행하지 않는다.

## 개발 모드

- `HM_DEV_MEMORY_PERSISTENCE=1`과 `NODE_ENV=development`가 모두 필요하다. production, test, NODE_ENV 미지정 환경에서는 플래그를 거부한다.
- `.env.local`에 플래그와 `.env.example`의 독립된 세션·암호화·내부 작업 키를 설정하고 `npm run dev`로 실행한다. DB URL과 S3 자격 증명은 필요하지 않다.
- 세션·할당량·공유 기록은 동일 서버 프로세스의 메모리를 쓴다. 서버 재시작 후에는 사라진다. 생산 환경이나 영구 공유 링크용으로 쓰지 않는다.
- 플래그가 없으면 PostgreSQL을 사용한다. DB 오류 시 메모리로 자동 전환하지 않는다.
- 시험은 실제 DB 연결을 막는 Pool 대역을 두고 세션 발급·검증, 저장형 공유 생성·읽기·소유자 삭제, 프로세스 내 상태 재사용, production 거부, 필수 키 검증을 확인한다.

## 과거 객체 정리

- S3 어댑터가 없는 런타임은 물리 객체 삭제를 건너뛴다. 기존 객체 참조는 삭제 대기 상태로 남겨 두며 삭제 완료 감사 기록을 만들지 않는다.
- 예약 정리 응답의 `generic.skippedItems`에 건너뛴 수를 표시한다. 이를 `attemptedItems`나 `completedItems`에 포함하지 않는다.
- 세션·공유·사용량·멱등 기록 정리는 계속한다. 일괄 처리량 확대와 보관 기간은 2-5에서 처리한다.
- 기존 S3 어댑터와 SDK는 보존한다. 어댑터를 명시적으로 공급하는 시험에서 대기 중인 객체를 다시 정리할 수 있음을 확인했다. 운영 런타임은 이 어댑터를 구성하지 않으며, 기존 `S3_*` 환경 변수도 읽지 않는다.
- 실제 DB·S3 접속, 기존 사용자 파일 삭제, 기존 마이그레이션 변경, H1 코드 변경은 없다.
