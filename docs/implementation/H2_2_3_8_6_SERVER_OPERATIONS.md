# H2 2-3 · 2-8 · 2-6 구현 보고

[H2] 2-3 오류 기록 — 부분(CI 후 자체 병합)
- 변경: 모든 남은 API 응답에 서버 생성 `x-request-id` 헤더를 추가했다. 알 수 없는 RangeError는 500 `SERVER_OPERATION_FAILED`로 바꾸고 입력 오류는 명시적인 목록만 400으로 허용한다.
- 검증: 요청 ID 상관관계, 조기 보안 거부, 정상 JSON 본문 유지, 비밀값·토큰·쿠키·공유 내용·IP가 섞인 오류 메시지 차단 시험을 통과했다. 예약 정리의 내부 실패도 구조화 로그를 남긴다.
- 사용자 영향: 문의에 응답 헤더의 요청 ID를 사용할 수 있다. 정상 응답 본문 형식은 유지한다.
- 남은 것: CI 후 병합.

[H2] 2-8 공개 진단 API 제거 — 부분(CI 후 자체 병합)
- 변경: `/api/substrate-compatibility`와 사용처가 사라진 진단 모듈을 제거했다.
- 검증: 타입 생성과 빌드에서 진단 경로 제거를 확인한다.
- 사용자 영향: 누락된 환경 변수 이름을 공개하던 경로는 404가 된다.
- 남은 것: CI 후 병합.

[H2] 2-6 DB 연결 설정 — 부분(CI 후 자체 병합)
- 변경: 앱 Pool 최대 연결 3, 연결 대기 5초, 유휴 10초, statement_timeout 5초, query_timeout 6초. README에 pooled URL 사용을 명시했다.
- 검증: Pool 생성자 대역으로 실제 런타임 구성 인자를 확인한다. 실제 DB에 접속하지 않는다.
- 사용자 영향: 요청이 DB 연결이나 쿼리를 무기한 기다리지 않으며 인스턴스별 연결 수를 제한한다. 마이그레이션 명령의 연결 설정은 별개다.
- 남은 것: CI 후 병합.

## 로그 개인정보 경계

- 시각·요청 ID·정적 경로 템플릿·오류 종류·메시지·스택을 JSON 한 줄로 기록한다. 동적 공유 토큰과 URL query는 경로에 포함하지 않는다.
- 임의의 드라이버 오류 메시지는 SQL 값이나 비밀값을 담을 수 있어 가린다. 코드에 등록된 내부 오류 메시지만 그대로 남긴다.
- 스택은 프레임 순서와 숫자 위치만 보존하고 파일 경로·함수 이름·첫 줄 오류 메시지는 가린다. 따라서 원문 로그보다 디버깅 정보가 적지만 데이터 노출을 막는다.
- 기존 세션 확인 중 DB 장애가 발생하면 새 세션 발급으로 삼키지 않고 API 오류 처리로 전달한다. 만료·잘못된 쿠키에 대한 교체 발급은 유지한다.
- 실제 적용 마이그레이션, H1 코드, 공유 암호화/저장 형식은 변경하지 않았다.
