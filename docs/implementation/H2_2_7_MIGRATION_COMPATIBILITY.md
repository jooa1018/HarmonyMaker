# H2 2-7 — 마이그레이션 확인 완화

[H2] 2-7 — 부분(A등급 판정 대기)

- 변경: `src/server/persistence/migrations.ts`의 실행 중 확인 함수, 별도 호환성 시험, README 배포 순서.
- 검증: 마이그레이션 집중 시험 16개 통과. SQL 문자열·MIGRATIONS 목록·체크섬 계산·적용 함수가 기준 커밋과 동일함을 비교했다. 최종 CI는 PR checks 참조.
- 사용자 영향: 먼저 추가형 마이그레이션을 적용한 DB에 구버전 앱이 잠시 남아 있어도 알려진 이력이 일치하면 요청을 계속 처리한다. 데이터·DDL은 변경하지 않는다.
- 필요한 판정: 런타임 검사 완화 승인. 승인 전 병합하지 않는다.

## 검사 정책

1. DB 이력이 코드보다 짧으면 기존처럼 `MIGRATION_REQUIRED`.
2. 코드가 아는 모든 항목의 버전·이름·체크섬은 정확히 일치해야 한다. 불일치는 `MIGRATION_HISTORY_DIVERGED`.
3. 뒤에 추가된 버전도 1부터 연속이어야 하며 누락·중복은 거부한다. 알지 못하는 SQL의 체크섬 내용은 판단하지 않는다.
4. 더 최신인 DB를 허용할 때 JSON 경고 `migration-schema-ahead`에 시각·codeVersion·databaseVersion만 남긴다. DB 문자열·SQL·연결 정보는 기록하지 않는다.
5. 적용 명령은 그대로 엄격하다. 구버전 마이그레이션 적용기가 앞선 DB를 변경하지 않으며 롤백한다. 배포할 코드로 `npm run migrate` 성공 후 앱을 배포한다.

검증기는 이력의 호환성만 판단한다. 실제 DB 변경의 하위 호환성은 추가형 마이그레이션 설계와 시험에서 보장해야 한다. 실제 DB 접속과 배포는 하지 않았다.
